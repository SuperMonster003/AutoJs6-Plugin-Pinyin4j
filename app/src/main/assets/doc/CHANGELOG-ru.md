# v1.3.0

###### 2026/09/11

* `Подсказка` `pinyin4j.readings()` и provider Node.js требуют обновленный хост AutoJs6 с контрактом readings v1; старые хосты могут продолжать использовать `of` и `as`
* `Функция` `pinyin4j.readings(text, options)` возвращает все упорядоченные словарные чтения по одной строке на кодовую точку Unicode, сохраняя немаппированный ввод как единственный вариант
* `Функция` `romanization` / `system` открывает Hanyu, Tongyong, Wade-Giles, MPS2, Yale и Gwoyeu Romatzyh; Hanyu поддерживает цифровые, отмеченные или опущенные тоны, регистр и формы `ü`
* `Улучшение` В конец Binder добавлены transaction `readings` и целочисленная capability `pinyin4j.readings.version = 1`; новые хосты вызывают ее только после согласования, а для старых плагинов безопасно возвращают один вариант Hanyu на точку
* `Улучшение` Добавлены строгие пределы источника, матрицы и UTF-8 JSON и Binder-проверка на Android 9/12/13/15; та же возможность открыта Node.js через явную capability хоста `pinyin4j`
* `Улучшение` Проверка сборки отклоняет непреднамеренные нативные зависимости и создает отчет JSON

# v1.2.0

###### 2026/09/01

* `Подсказка` Несколько чтений и шесть систем романизации пока существуют только как протестированное ядро плагина и проект контракта; `pinyin4j.readings()` не является публичным API сценариев до обновления AIDL и маршрутов хоста AutoJs6
* `Исправление` `of` больше не теряет пробелы словаря и не разделяет символы дополнительных плоскостей: теперь он обходит кодовые точки Unicode, преобразует все реальные записи включая `〇`, целиком сохраняет ввод без записей и выравнивает разделители по кодовым точкам
* `Исправление` `pinyin4j.as(text)` теперь преобразует только полные корректные слоги с цифровым тоном, сохраняет неверные или встроенные в буквенно-цифровой текст фрагменты, обрабатывает регистр и `v` / `u:` / `ü`, а также правильно понимает обычное написание `ue`, например `jue4` -> `juè`
* `Улучшение` Фактическое покрытие словаря закреплено полным тестом BMP: 20 378 записей, из них 20 377 в U+4E00-U+9FA5, а оставшаяся для `〇`; также проверяются 525 пробелов старого диапазона и отпечаток SHA-256 корпуса
* `Улучшение` Добавлено протестированное ядро всех кандидатов для Hanyu, Tongyong, Wade-Giles, MPS2, Yale и Gwoyeu Romatzyh, а также описан проект добавочного JSON AIDL, согласования возможностей и отката к старой реализации
* `Улучшение` Добавлен реестр рисков pinyin4j 2.5.1 с хешами бинарного файла и исходников, выводами об upstream и метаданных лицензии, известными границами и воротами для обновления или fork
* `Улучшение` Добавлены воспроизводимые базовые показатели JVM и точки входа Android Service/AIDL, анализатор ZIP/ресурсов release APK и основанное на измерениях сравнение выбора родственных плагинов

# v1.0.0

###### 2026/07/15

* `Функция` Сервис плагина Pinyin4j: идентификатор плагина `pinyin4j`, автоматически обнаруживается и вызывается AutoJs6 через `org.autojs.plugin.PINYIN4J`, оборачивает библиотеку `com.belerweb:pinyin4j:2.5.1`
* `Функция` API преобразования пиньиня: `pinyin4j.of(text, options)` посимвольно превращает китайский текст в пиньинь; строка, переданная вторым аргументом, сразу используется как разделитель
* `Функция` API восстановления тонов: `pinyin4j.as(text)` превращает пиньинь с цифровыми тонами (например `han4`) в пиньинь с тоновыми знаками (например `hàn`), соответствует методу AIDL интерфейса `asTone`
* `Функция` Гибкая система параметров: псевдонимы вроде `case` / `tone` / `v` / `sep` и краткие значения вроде `MARK` / `NUMBER` / `NO`; недопустимые значения вызывают локализованные сообщения об ошибках
* `Функция` Многоязычные ресурсы: метаданные плагина и инструкции охватывают 10 языков
* `Функция` README и CHANGELOG генерируются как многоязычный Markdown из JSON источников скриптом `.python/generate_markdown.py`
