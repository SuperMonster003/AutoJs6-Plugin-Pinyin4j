### Введение

******

Плагин Pinyin4j (Pinyin4j Plugin) добавляет в AutoJs6 легковесное преобразование китайского текста в пиньинь. После установки скрипты могут через глобальный объект `pinyin4j` преобразовывать китайский текст в пиньинь посимвольно, настраивая по необходимости регистр букв, формат тонов, способ записи `ü` и разделитель слогов; также имеется утилитарный метод, превращающий текст с цифровыми тонами в тоновые знаки.

Плагин представляет собой отдельно устанавливаемый APK, работающий в собственном процессе; AutoJs6 обнаруживает его автоматически через механизм плагинов и общается с ним по AIDL. Преобразование выполняет классическая Java библиотека [pinyin4j](https://github.com/belerweb/pinyin4j) (`com.belerweb:pinyin4j:2.5.1`); измеренный release занимает лишь 349 KiB, а преобразование целиком происходит локально на устройстве без доступа к сети. Начиная с AutoJs6 v6.8.0 модуль `pinyin4j` хоста реализуется этим плагином.

Этот плагин и [Pinyin](https://github.com/SuperMonster003/AutoJs6-Plugin-Pinyin) являются родственными плагинами: этот плагин при крошечном размере дает простую и надежную посимвольную транскрипцию, а плагин Pinyin содержит полные словари и сегментацию Jieba, поддерживая разрешение неоднозначных чтений и режим фамилий для сценариев, где важна точность чтения. Оба можно установить одновременно; подробности в разделе `Сравнение Родственных Плагинов` ниже.

### Основные Возможности

******

- Работает из коробки: после установки AutoJs6 обнаруживает плагин автоматически, перезапуск хоста не нужен; скрипты сразу используют глобальный объект `pinyin4j`.
- Предельная легковесность: измеренный release занимает лишь 349 KiB, реализация на чистой JVM без каких-либо нативных библиотек, совместим со всеми архитектурами CPU.
- Три формата тонов: без тонов, цифровые тоны (`han4`) и тоновые знаки (`hàn`), на выбор.
- Гибкий вывод: настраиваемый регистр букв, три способа записи `ü` (`lv` / `lu:` / `lü`) и произвольный разделитель слогов.
- Тоновая утилита: `pinyin4j.as(text)` за один шаг превращает текст с цифровыми тонами в форму с тоновыми знаками.
- Нестрогие значения: параметры не зависят от регистра и принимают несколько кратких псевдонимов (например `tone: "MARK"`); недопустимые значения дают локализованные сообщения об ошибках.
- Полностью офлайн: преобразование опирается на встроенные данные и выполняется локально на устройстве, без каких-либо сетевых запросов.
- Многоязычность: метаданные плагина, инструкции, README и журнал изменений доступны на 10 языках.

### Использование

******

1. Обновите AutoJs6 до внутренней сборки 3923 (6.7.1 Alpha4) или выше; начиная с v6.8.0 возможности пиньиня полностью переданы плагинам, поэтому рекомендуется последняя версия.
2. Скачайте APK плагина со страницы [Releases](https://github.com/SuperMonster003/AutoJs6-Plugin-Pinyin4j/releases) и установите его на устройство с AutoJs6, либо установите его онлайн прямо из центра плагинов AutoJs6.
3. Откройте центр плагинов AutoJs6, убедитесь, что плагин `Pinyin4j` распознан, выдайте разрешение и включите его.
4. Вызывайте глобальный объект `pinyin4j` прямо в скриптах, следуя примерам из раздела `Быстрый Старт` ниже; также можно сначала выполнить скрипт из раздела `Быстрая Самопроверка`, чтобы убедиться, что плагин активен.

> Плагин поставляется единственным универсальным пакетом (чистая JVM, без вариантов под архитектуры CPU) и поддерживает устройства с Android 7.0 (API 24) и выше. У плагина нет собственного интерфейса, он не создает значок на рабочем столе; AutoJs6 обнаруживает его и управляет им централизованно.

### Быстрый Старт

******

Базовое преобразование: по умолчанию выводится пиньинь строчными буквами без тонов; вторым аргументом можно сразу передать разделитель:

```javascript
console.log(pinyin4j.of("汉语拼音"));                             // "hanyupinyin"
console.log(pinyin4j.of("汉语拼音", " "));                        // "han yu pin yin"
console.log(pinyin4j.of("汉语拼音", { tone: "MARK", sep: " " })); // "hàn yǔ pīn yīn"
```

Цифровые тоны и способы записи `ü`:

```javascript
console.log(pinyin4j.of("旅游", { tone: "NUMBER" }));             // "lv3you2"
console.log(pinyin4j.of("旅游", { tone: "NUMBER", v: "U:" }));    // "lu:3you2"
console.log(pinyin4j.of("旅游", { tone: "MARK" }));               // "lǚyóu"
```

Тоновая утилита: превращение текста с цифровыми тонами в тоновые знаки:

```javascript
console.log(pinyin4j.as("han4 yu3 pin1 yin1"));                   // "hàn yǔ pīn yīn"
```

### Параметры

******

`pinyin4j.of(text, options)` поддерживает следующие параметры (в скобках указаны краткие имена ключей):

| Параметр | По умолчанию | Описание |
|---|---|---|
| `caseType` (`case`) | `LOWERCASE` | Регистр вывода: `LOWERCASE` строчные, `UPPERCASE` прописные |
| `toneType` (`tone`) | `WITHOUT_TONE` | Формат тонов: `WITHOUT_TONE` без тонов, `WITH_TONE_NUMBER` цифровые тоны, `WITH_TONE_MARK` тоновые знаки |
| `vCharType` (`v`, `vChar`) | `WITH_V` | Способ записи `ü`: `WITH_V` (`lv`), `WITH_U_AND_COLON` (`lu:`), `WITH_U_UNICODE` (`lü`); в формате тоновых знаков по умолчанию переключается на `WITH_U_UNICODE` |
| `separator` (`sep`) | `""` | Разделитель между слогами, любая строка; завершающий разделитель в конце вывода удаляется |

Значения не зависят от регистра и принимают краткие псевдонимы, например `tone: "MARK"` / `"NUMBER"` / `"NO"`, `case: "UP"` / `"LOW"`, `v: "V"` / `"U:"` / `"U"`. Передача недопустимого значения вызывает исключение с локализованным сообщением.

### API Скриптов

******

Глобальный объект `pinyin4j` предоставляет следующие методы (прямой вызов `pinyin4j(text, options)` эквивалентен `pinyin4j.of`):

```text
pinyin4j(text, options?)      -> string
pinyin4j.of(text, options?)   -> string
pinyin4j.of(text, separator)  -> string
pinyin4j.as(text)             -> string
```

- `of` обходит кодовые точки Unicode и напрямую запрашивает закрепленный словарь pinyin4j 2.5.1: преобразуются все 20 378 символов BMP с записями (включая `〇`), а точки без записей и из дополнительных плоскостей сохраняются целиком. По-прежнему выбирается только первое чтение без контекстного разрешения неоднозначности.
- Вторым аргументом `of` может быть как объект параметров, так и просто строка, используемая как разделитель.
- `as` преобразует только полные распознанные слоги с цифрой тона от `0` до `4`, сохраняет регистр и принимает `v`, `u:` или `ü`; неверные слоги, цифра `5` и фрагменты рядом с буквами или цифрами остаются без изменений. Этот метод соответствует `asTone` в AIDL интерфейсе плагина.
- Значения параметров не зависят от регистра и принимают несколько кратких форм (см. `Параметры` выше); недопустимые значения вызывают исключение с локализованным сообщением.
- Все методы возвращают результат синхронно; первое преобразование лениво загружает словарь pinyin4j и поэтому медленнее установившихся вызовов, что отражено в тесте производительности.

### Частые Вопросы

******

#### Как убедиться, что плагин работает?

Откройте центр плагинов AutoJs6; если плагин `Pinyin4j` виден и включен, хост его распознал. Затем запустите скрипт из раздела `Быстрая Самопроверка` выше; вывод `pinyin` означает, что все работает.

#### Скрипт сообщает об отсутствии плагина или что `pinyin4j` недоступен?

Убедитесь, что внутренняя сборка AutoJs6 не ниже 3923, а плагин установлен, авторизован и включен в центре плагинов. Начиная с AutoJs6 v6.8.0 хост больше не содержит библиотеку pinyin4j; эту возможность целиком обеспечивает данный плагин.

#### Почему в списке приложений и на рабочем столе нет значка плагина?

Так и задумано. У плагина нет собственного интерфейса, и он не создает значок запуска; после установки AutoJs6 обнаруживает и вызывает его в фоне, а все взаимодействие происходит внутри AutoJs6.

#### Чтение иероглифа с несколькими чтениями не соответствует ожиданиям (например "重庆" не читается как chongqing)?

Плагин преобразует посимвольно и всегда берет первое словарное чтение, не привлекая контекст словосочетаний; это неотъемлемый компромисс легковесного подхода. Если нужны разрешение неоднозначных чтений, словари словосочетаний или чтения фамилий, используйте родственный плагин [Pinyin](https://github.com/SuperMonster003/AutoJs6-Plugin-Pinyin).

#### Почему `pinyin4j.asTone(text)` из документации или старых скриптов не работает?

На стороне хоста метод называется `pinyin4j.as(text)`; `asTone` является именем метода в AIDL интерфейсе плагина, и ведут они себя одинаково. В скриптах используйте `pinyin4j.as(text)`.

#### Обращается ли плагин к сети или запрашивает чувствительные разрешения?

Нет. Данные для преобразования встроены в установочный пакет, а преобразование происходит локально на устройстве; манифест плагина объявляет только разрешение плагина для связи с AutoJs6, не запрашивая сети, хранилища и других чувствительных системных разрешений.

#### Как выбрать между этим плагином и родственным плагином Pinyin?

Выбирайте этот плагин, когда нужна лишь легковесная посимвольная транскрипция и важен размер установочного пакета; выбирайте [Pinyin](https://github.com/SuperMonster003/AutoJs6-Plugin-Pinyin), когда нужны неоднозначные чтения, сегментация, словосочетания или чтения фамилий. Они не конфликтуют и могут быть установлены вместе; подробности в разделе `Сравнение Родственных Плагинов` ниже.

### Разрешения И Безопасность

******

Плагин спроектирован так, чтобы поверхность данных и разрешений была минимальной:

- Минимальные разрешения: манифест объявляет только разрешение плагина AutoJs6 (`org.autojs.permission.PLUGIN`), без запросов сети, хранилища, камеры и других чувствительных системных разрешений.
- Локальное преобразование: преобразуемый текст передается только внутри устройства через Binder; данные преобразования полностью встроены, все происходит офлайн, и данные не покидают устройство.
- Подпись и авторизация: AutoJs6 проверяет подпись плагина, а плагин должен быть авторизован и включен в центре плагинов, прежде чем скрипты смогут его вызывать; сервис и точка пробуждения защищены разрешением плагина, поэтому сторонние приложения не могут вызывать их напрямую.
- Открытость и проверяемость: код плагина и конвейер генерации документации полностью открыты, а преобразование выполняет широко используемая библиотека с открытым исходным кодом pinyin4j.

Устанавливайте плагин только с официальной страницы [Releases](https://github.com/SuperMonster003/AutoJs6-Plugin-Pinyin4j/releases) или из центра плагинов AutoJs6; пакет неизвестного происхождения может быть подменен, даже если имя и номер версии выглядят одинаково.

******

| Критерий | [Pinyin4j](https://github.com/SuperMonster003/AutoJs6-Plugin-Pinyin4j) | [Pinyin](https://github.com/SuperMonster003/AutoJs6-Plugin-Pinyin) |
|---|---|---|
| Базовая реализация | Классическая Java библиотека `pinyin4j` | Встроенные словари + сегментация Jieba |
| Глобальный объект | `pinyin4j` | `pinyin` |
| Несколько чтений | Не поддерживается, всегда первое чтение | Поддерживается, может вернуть все варианты |
| Сегментация и словосочетания | Не поддерживается, посимвольное преобразование | Поддерживается (словарь словосочетаний + Jieba) |
| Режим фамилий | Не поддерживается | Поддерживается |
| Форма вывода | Строка с настраиваемым разделителем | Двумерный массив вариантов (комбинируется через `compact()`) или компактная строка |
| Стили и форматы | 3 формата тонов + регистр + способы записи `ü` | 6 стилей пиньиня |
| Размер пакета | 349 KiB ([измерение release](https://github.com/SuperMonster003/AutoJs6-Plugin-Pinyin4j/blob/master/docs/performance/apk-size-baseline-2026-09-01.md)) | 5.95 MiB ([измеренный full release](https://github.com/SuperMonster003/AutoJs6-Plugin-Pinyin/blob/master/docs/size/packaging-strategy-2026-09-01.md), встроенные словари) |
| Профиль производительности | Легкий посимвольный путь; [измерения JVM/Android](https://github.com/SuperMonster003/AutoJs6-Plugin-Pinyin4j/blob/master/docs/performance/conversion-baseline-2026-09-01.md) | [Измерение сегментатора](https://github.com/SuperMonster003/AutoJs6-Plugin-Pinyin/blob/master/docs/benchmarks/segmenter-reuse-2026-09-01.md); более тяжелые словарь, сегментация и многозначные чтения, зависящие от режима |
| Подходит для | Приоритет размера и простоты: быстрая посимвольная транскрипция | Приоритет точности: неоднозначные чтения, словосочетания, имена |

Два плагина не зависят друг от друга и не конфликтуют; после установки обоих скрипты могут по необходимости вызывать `pinyin4j` и `pinyin` по отдельности. Подробности о плагине Pinyin смотрите в [AutoJs6-Plugin-Pinyin](https://github.com/SuperMonster003/AutoJs6-Plugin-Pinyin).

### Интерфейс Плагина

******

Следующая информация предназначена разработчикам хоста AutoJs6 и плагинов; хост использует эти идентификаторы для обнаружения плагина и согласования возможностей:

```text
application id: io.github.supermonster003.autojs6.plugin.pinyin4j
plugin id: pinyin4j
engine: pinyin4j
variant: default
discovery action: org.autojs.plugin.PINYIN4J
discovery category: pinyin4j
wake action: org.autojs.plugin.action.WAKE
binder interface: IPinyin4jPlugin
binder methods: getInfo / of / asTone
minimum host build: 3923
native library: none (pure JVM, all ABIs)
library: com.belerweb:pinyin4j:2.5.1
```

`Pinyin4jPluginService` отвечает на action `org.autojs.plugin.PINYIN4J` (category `pinyin4j`) и предоставляет 3 метода через AIDL интерфейс `IPinyin4jPlugin`; параметры `of` передаются через `Bundle` (ключи: `caseType` / `toneType` / `vCharType` / `separator`), а недопустимые значения вызывают `IllegalArgumentException` с локализованным сообщением. Сервис и `WakeActivity` защищены разрешением `org.autojs.permission.PLUGIN`, поэтому сторонние приложения не могут вызывать их напрямую.

### Сборка

******

Этот раздел предназначен разработчикам, желающим собрать плагин из исходников.

Собрать debug APK:

```powershell
.\gradlew.bat :app:assembleDebug
```

Собрать release APK (единственный универсальный пакет; после настройки подписи в неотслеживаемом `sign.properties` подписывается автоматически):

```powershell
.\gradlew.bat :app:assembleRelease
```

Для создания проверенного архива выпуска запустите `py .python/prepare_release.py`. Скрипт проверяет сгенерированную документацию, собирает и проверяет подписанный universal APK, сверяет метаданные версии, вычисляет CRC32 и SHA-256, затем атомарно записывает APK, `SHA256SUMS.txt` и английский `RELEASE_NOTES.md` в `app/releases/v<версия>`.

Параметры сборки собраны в `version.properties`: минимальный SDK 24 (Android 7.0), целевой SDK 36, текущая версия 1.2.0.

### Локализация И Генерация Документации

******

```text
.readme/common.json
.readme/lang_*.json
.readme/template_readme.md
.readme/template_plugin_instruction.md
.changelog/lang_*.json
.changelog/template_changelog.md
.python/generate_markdown.py
app/src/main/assets/doc/CHANGELOG-*.md
app/src/main/res/values-*/strings.xml
app/src/main/res/raw-*/plugin_instruction.md
```

`strings.xml` содержит локализованное описание плагина и сообщения об ошибках, а `plugin_instruction.md` содержит инструкции, отображаемые в центре плагинов хоста. README, журнал изменений и инструкции генерируются из JSON источников: отредактируйте источники в `.readme/` и `.changelog/`, затем выполните `py .python/generate_markdown.py`, чтобы пересоздать все артефакты; сгенерированные артефакты никогда не правятся вручную. Команда `py .python/generate_markdown.py --check` проверяет синхронность источников и артефактов.
